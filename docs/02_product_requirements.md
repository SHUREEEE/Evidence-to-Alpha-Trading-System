# Evidence-to-Alpha Trading System 产品需求文档

版本：v0.1.0 MVP

## 1. 产品目标

在严格使用当时可得新闻证据的条件下，验证事件信号能否为既有多因子策略带来稳定、可解释、扣除成本后的增量信息。系统必须允许 PROMOTE、REJECT 和 INCONCLUSIVE 三种结论。

## 2. 用户与核心场景

- 量化研究员导入新闻系统只读快照，生成事件研究和信号。
- 组合研究员把事件信号作为有限幅度 overlay 叠加到因子基线。
- 风险或验证人员检查泄漏、成本、安慰剂、延迟和样本外证据。
- 研究负责人追溯任一订单到事件版本、原始证据、映射和因子版本。

## 3. 范围

MVP 包括事件契约、版本选择、实体映射、事件信号、事件研究、组合叠加、Paper OMS、验证结论、审计产物、CLI 和只读 API。

MVP 不包括新闻采集或前端、券商连接、真实资金、生产凭据、复杂机器学习、实时撮合和高可用集群。

## 4. 功能需求

### FR-01 事件数据适配

系统必须读取带 event_id、event_version、published_at、observed_at、asof、证据 ID 和影响主体的事件版本。相同事件版本不可被不同内容覆盖。

### FR-02 Point-in-time 选择

任一运行只可选择 asof 不晚于运行截止时间的最新版本；未来版本不得影响历史运行。

### FR-03 实体映射

公司或行业实体映射到股票代码、行业与影响倍数；失败映射必须披露，不得静默忽略。

### FR-04 信号生成

方向、可信度、新颖性、冲突状态和时间衰减共同决定事件信号。每条信号必须带配置哈希、事件版本和证据 ID。

### FR-05 事件研究

计算 1、3、5、20 个交易日的绝对和相对基准收益；数据不足的窗口必须标记缺失。

### FR-06 信号融合

提供因子基线、事件基线和因子加事件 overlay。叠加受单票调整、换手和单票最终权重限制。

### FR-07 Paper OMS

从目标权重生成订单，在下一可交易日开盘按滑点和手续费成交，维护现金、持仓与 PnL，并完成账本闭合。

### FR-08 研究验证

必须执行时间泄漏、证据完整性、版本不可变、T+1、成本翻倍、延迟一日、安慰剂、基线独立对比和样本量检查。

### FR-09 结果与追溯

输出研究结论、门禁结果、事件研究、信号、订单、成交和 SQLite 账本。任一订单可追溯到因子版本；事件调整订单还须追溯到事件和证据。

### FR-10 只读服务

提供健康检查、最新运行、信号、订单、成交与事件研究的只读 JSON 端点。

## 5. 非功能需求

- 确定性：相同输入和配置产生相同配置哈希、信号和订单。
- 安全：不读取券商凭据，不提供写交易端点。
- 可复现：运行报告记录输入摘要、配置和版本。
- 可部署：Python 3.11+ 直接运行；提供 Docker 配置。
- 可测试：核心领域逻辑由标准库单元测试覆盖。
- 可审计：重要结论区分已验证事实、推断、未知和决策。

## 6. 验收标准

1. 未来事件版本无法进入历史运行。
2. 观察时间早于发布时间的事件被拒绝。
3. 相同 event_id/event_version 的不同内容被拒绝。
4. 所有事件信号引用的证据均存在。
5. 成交日期严格晚于信号截止日期。
6. 组合 overlay 不超过配置限制。
7. 现金、持仓、市值、费用和总权益闭合到 0.01。
8. 因子基线和事件增强结果独立报告。
9. 样本不足时返回 INCONCLUSIVE，而不是继续调参。
10. 自动化测试全部通过，发布证据完整。
